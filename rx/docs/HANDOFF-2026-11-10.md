## WIRKUNG DER LETZTE OFFENE PUNKT (morgen zuerst!)
ntfy antwortet der Brücke mit **401 Unauthorized**.
- Benutzer `librerid-bridge` existiert, ACL `rw` auf Topic `librerid` ✓
- Passwort in `/opt/librerid/ntfy-bridge-pass.txt` = identisch zu dem im Test-Curl.
- Aber: der **gespeicherte bcrypt-Hash passt nicht** zum Datei-Passwort
  (vermutlich beim Anlegen durch Chat-Tool-Zensur verstümmelt).
- **Fix**: Server stoppen, dann
  `read PW < /w/ntfy-bridge-pass.txt; NTFY_PASSWORD=*** ntfy user change-pass librerid-bridge`
  (Kommando heißt `change-pass`, NICHT `update`!), Server starten,
  dann testen: `curl -u 'librerid-bridge:<pw>' -d probe http://127.0.0.1:2586/librerid`
  → erwartet HTTP 2xx/4xx-frei, und Push auf dem Handy (App: Server
  `ntfy.fsg-schwarzenbach-saale.de`, Topic `librerid`, mit Login abonnieren).

## Merksätze diese Session (Zensur-Fallen im Chat-Tool!)
- `$(...)-Kommandos` und `:"`-Folgen werden beim Kopieren in die Shell gern
  verstümmelt → Skripte per `tee <<'EOF'` schreiben, `read PW < datei` +
  `chr(61)`-Tricks statt `$(cat)` und `=`/`:` in String-Literalen.
- ntfy v2.37: `ntfy user` Unterbefehle = add/remove/change-pass/... ;
  Passwort-Setzen nur über Env `NTFY_PASSWORD`.
- `mosquitto_pub` gegen TLS-Broker braucht `--cafile` (Root+Chain), sonst
  "wrong version number" (Klartext-Anlauf) bzw. "unknown ca" (Root fehlt).
